# Veyra 0.1.0-alpha.3

Veyra 0.1.0-alpha.3 is an early Linux prerelease using the published Bitwarden Rust SDK `rust-v4.0.0`, pinned to commit `b865d1db0025d9d12bea871a3a131c05aaeed205`.

- Read-only V1 personal Vaultwarden vaults, including PBKDF2/Argon2 and authenticator TOTP two-factor login.
- Native Quick Access, local search, protected field copying and explicit locking across both windows. Clipboard clearing is best effort; external history managers may retain values.
- Program information and optional daily update checks for published GitHub Releases. Checks do not install updates automatically.
- SDK release pin and third-party notices are included in the package. The source archive contains Veyra, vendored Rust sources and isolated Linux x86_64/glibc pnpm package contents with their license files. See SOURCE-BUILD.md for the remaining online registry-metadata verification and system/toolchain prerequisites.

Organizations, editing, encrypted offline unlock, browser autofill and a system-wide shortcut remain unsupported. Quick Access works while Veyra is focused. This preview has not received independent production-security certification.

Validation: 70 local tests passed (33 frontend units, 24 Rust defaults, 11 browser E2E, two separately executed real Vaultwarden tests), along with strict types/lint/Clippy, static generation, the optimized native build and native-host search/clipboard/lock smoke. The tagged CI run is https://github.com/Lucas-Gruber/Veyra/actions/runs/40732003146; all 70 tests, the optimized Linux build and installed Flatpak search/copy/lock verification passed there for the exact tagged source. The only failed job was the dependency security audit; automatic publication was skipped.

A fresh unsuppressed audit on 2026-10-29 (also independently repeated by the main-branch CI) found exactly the same single vulnerability and five existing warnings, with no additional findings.

Security status: the released SDK still contains rsa 0.10.0-rc.19 and RUSTSEC-2023-0071. Raw cargo audit fails on that finding; switching to a published SDK does not repair the library. The current personal-only client does not import the account RSA private key, and source review found no reachable call to the affected RSA private-decryption operation. This is a scoped assessment, not a proof or certification. The project owner explicitly authorized publication of this exact Alpha3 build on 2026-10-29 after reviewing the unresolved finding and scoped assessment. This is a one-time, documented risk exception for RUSTSEC-2023-0071 in rsa 0.10.0-rc.19, limited to Veyra 0.1.0-alpha.3 at source commit d7506000f7b5b66ef8958339949079811e20ca0d. It does not fix the library, certify security, waive other findings or authorize future releases. Raw audits remain failing and unchanged; publication is manual under this owner-approved exception.

The release assets were prepared by https://github.com/Lucas-Gruber/Veyra/actions/runs/40914689543 and downloaded again for verification. All five SHA256SUMS entries passed; the Flatpak matches the tested CI artifact. The source archive identity, published SDK pin, portable Cargo vendor configuration and GPL notices were checked. The original CI security log, scoped assessment and validation metadata accompany the build. They are preserved as pre-approval evidence: publication_authorized=false in the validation snapshot records its staging-time state; the subsequent owner decision is recorded in these release notes.
